---

## 1. サービスの本質（最重要）

- **人生の意思決定を支援する AI パートナー**。目標と日々の行動をつなぎ、自分らしい人生の実現を伴走する。
- **これではない**：AIチャット / タスク管理 / KPI管理 / 目標管理ツール / 業務システム。
- 価値：「何をすればいいか分からない」を「今日はこれでいい」に変える。
- 感情設計：**焦りを下げ、希望を上げる**。操作後に少し呼吸が楽になる。
- 主役は **ユーザー自身の人生**。AI は画面の中心に置かず、必要な時にだけ静かに現れる。

### First 5 seconds（開いて5秒で感じさせる）
- ここなら自分の人生を整理できそう
- 押し付けられず、一緒に考えてもらえそう
- 焦らなくても大丈夫そう

---

## 2. 体験の骨格：人生でぶつかる5つの壁 → 5つの体験

| 壁 | 対応する体験 |
|---|---|
| ① 現在地が分からない | Self / Compass：いまの自分を整理する |
| ② 行き先が決まらない | Compass / Vision：価値観と理想を言語化する |
| ③ 行動へ落とし込めない | Route / Journey：今日の一歩に変換する |
| ④ 続けられない | Journey / Reflect：できたことを実感する |
| ⑤ 変化に対応できない | Update：今の自分に合わせて見直す |

**UX原則**：一画面一役割 / 次の一歩が自然に分かる / 比較対象は他人ではなく過去の自分 / 心が疲れない提案量。

---

## 3. 画面一覧と目的

| 画面 | 一言 | 目的（閉じたとき分かること） |
|---|---|---|
| 🏠 Dashboard | 人生のコックピット | 今どこにいて、次に何をすればいいか |
| 🧭 Compass | 人生の方向を見つける | どんな人生を歩きたいのかが言葉になる |
| 🎯 Vision | 理想の人生を描く | 目的地（理想の暮らし・仕事・お金 等）が明確になる |
| 📍 Route | 人生設計をつくる | どの順番で人生を進めればいいか |
| 🚶 Journey | 今日の一歩へつなげる | 今日、何をすればいいか |
| 📝 Reflect | 振り返る | 昨日より成長した自分を実感できる |
| 🔄 Update | 人生を更新する | 今の自分に合った人生設計に更新できる |
| ⚙ Settings | 信頼と管理 | 自分の情報・AIの理解・プライバシーを確認できる |

> Vision は事業計画書では情報設計上の概念だが、UX では「理想を描く場所」として独立画面にする（資料の提案どおり）。

## 4. 画面ごとの中身（モックで表現する要素）

- **Dashboard**：穏やかな挨拶 / 今日の一歩 / 今週の道筋（Compass→Route→Journey）/ 次の節目 / AIからの小さな提案 / 現在地。進捗率・大量KPIは出さない。
  - 代表コピー：「焦らなくて大丈夫です。今日は10分だけ、理想の暮らしを書き出してみましょう。」
- **Compass**：大切にしたいこと / やりたいこと / 避けたいこと / 人生理念の下書き / AIからの問い。AIは答えを決めず質問・整理の補助。
- **Vision**：理想の暮らし / 仕事 / お金 / 健康 / 人間関係 / 実現したい未来。入力済み仮データをカードで表示。
- **Route**：5年→3年→1年→3か月→今月→今日 の柔らかいタイムライン。必要なお金・スキル・経験を補助情報に。ガントチャートにしない。
- **Journey**：今日の一歩（最大3件）/ 今週 / 今月。チェックボックスは軽く、Todoアプリに見せない。
- **Reflect**：できたこと / 気づいたこと / 今日の気持ち / 過去の自分からの変化 / 次に試したいこと / AIの穏やかな要約。未達を赤で警告しない。
- **Update**：仕事 / お金 / 健康 / 家族 / 価値観の変化 / AIが整理した影響範囲 / 更新候補。AIは確定せず、最後はユーザーが確認。
- **Settings**：プロフィール / AIが理解しているあなた / AI Memory / データ連携 / プライバシー / データの修正・削除。

---

## 5. AI の見せ方

- フルスクリーンチャットにしない。画面の文脈に合わせた **小さな提案・問い・整理結果** として表示。
- 画面ごとの役割：Compass=問いかける / Route=整理する / Journey=絞る / Reflect=認める / Update=見直す。
- 重要情報（価値観・人生理念・目標・ライフイベント）は AI が確定せず「更新候補」としてユーザー確認を通す。
- 温度感：先生ではなく伴走者。命令形を避け「一緒に整理しましょう」「今日はここまでで十分」。

---

## 6. デザインガイドライン

- **色**：Base=ホワイト / Surface=薄いアイボリー・ライトグレー / Main=落ち着いたブルー / Sub=優しいグリーン / Accent=控えめオレンジ / Error=レッド（多用しない）。
- **文字**：見出しは大きく、本文は読みやすく。小さすぎる補足文字を多用しない。日本語フォントが自然に見えるように。
- **余白**：画面密度を下げ、1画面1目的。詰め込むより次の一歩を明確に。
- **使うUI**：大きめカード / ラインアイコン / 余白のある入力欄 / 静かなAI提案 / 1つの主要CTA。
- **避けるUI**：大量のボタン / KPIダッシュボード / 複雑なグラフ / チャット全面表示 / 赤い警告の多用。
- **CTA**：「保存」より「今日の一歩へ」「一緒に整理する」「下書きを確認する」。

### マイクロコピー指針（× → ○）
- 管理します → 一緒に整理します
- 目標未達です → 今日はここまでで大丈夫です
- AIが決定しました → 更新候補を作りました
- タスクを消化しましょう → 今日の一歩を選びましょう
- 進捗が遅れています → 今の状況に合わせて見直せます

声のトーン：落ち着いている / 押し付けない / 短い / やさしい / でも曖昧すぎない。

## 7. 画面構成（デスクトップ）

- 左：サイドナビゲーション（Dashboard / Compass / Vision / Route / Journey / Reflect / Update / Settings）
- 上：ページ名 + 短い説明 + ユーザーアイコン
- 中央：各画面のメインコンテンツ

## 8. 実装への落とし込み（このモックの方針）

- Streamlit + streamlit-option-menu + カスタムCSS（`assets/styles.css`）。
- 仮データは `data/mock_data.py` に集約。共通UIは `components/` に集約。
- 画面本体は `pages/*.py` に `render()` 関数として実装し、`app.py` が option_menu の選択に応じて呼び出す。
- **注意（Streamlit仕様）**：`pages/` フォルダを置くと Streamlit が自動でマルチページ・ナビを生成し、独自の option_menu と二重化する。これを避けるため `.streamlit/config.toml` で `showSidebarNavigation=false` を設定し、独自ナビに一本化する。
